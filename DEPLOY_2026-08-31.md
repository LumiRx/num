## 4 · Check it in the first ten minutes

```bash
# health should be ok
curl -s https://app.itsnum.com/api/health

# NEW — what Twilio Verify actually did with your sign-in codes
curl -s -H "X-Admin-Key: $ADMIN_KEY" "https://app.itsnum.com/api/admin/verify?hours=48"

# the brain probe no longer skips the two brains that matter:
# claude and haiku should now report ok true/false, never null
curl -s -H "X-Admin-Key: $ADMIN_KEY" "https://app.itsnum.com/api/brains?probe=1"
```

The Verify endpoint gives a one-line verdict — `delivering`, `failing`,
`partial`, `pending`, `quiet`, `misconfigured` or `unreachable` — plus the
carrier error code behind it. If it says **failing** with 30034, a Messaging
Service is attached to your Verify service and is cancelling the A2P exemption;
detach it in Verify → Services → Messaging configuration.

Then, in the database:

```sql
-- Verify outcomes now land in the same table as everything else.
-- Rows keyed VL… are Verify; SM… are Programmable Messaging.
SELECT message_sid, to_phone, status, error_code, datetime(created_at,'unixepoch')
FROM num_sms_delivery ORDER BY created_at DESC LIMIT 10;

-- A recovered brain should carry NO last_error.
SELECT brain, fails, class, last_error, cooldown_until FROM num_brain_state;
```

## What is in this release

**Sign-in codes**
- `/api/admin/verify` — reads Twilio's Verification Attempts API and says
  plainly whether codes are reaching carriers. Nothing had ever asked before.
- Cron folds Verify outcomes into `num_sms_delivery` every 5 minutes, so one
  table finally covers both message pipes.
- Resend button on both code screens, with a countdown and an honest message
  when the previous code is already known to have failed.
- **Bug:** the resend cooldown read a column the Verify path sets to NULL, so
  there was no rate limit in production at all.
- **Bug:** `POST /me` recovery sent a paid SMS to any number, unauthenticated
  and unthrottled. Both mint paths now share one gate — 60s cooldown, 5
  successful sends per number per hour.
- **Bug:** a *failed* send started the cooldown, telling someone "a code is on
  its way" when nothing had left.

**The brain**
- New `blocked` failure class. A 403 from an edge or WAF is no longer read as a
  dead API key and no longer stands a working brain down for an hour.
- The brain health check makes a real one-token call, and only for a brain whose
  cooldown has lapsed with nothing proven. A healthy chain probes nothing.
- `/api/brains?probe=1` no longer reports `ok: null` for `claude` and `haiku` —
  the only two brains that have ever taken the product down.
- **Bug:** a recovered brain kept displaying its old error, so a healthy brain
  read as broken for hours.
