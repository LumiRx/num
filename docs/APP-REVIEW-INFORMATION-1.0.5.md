## Field: Sign-In Required

**Change this to YES.**

It was set to *No*, and that was right when the app was judged on the
concierge alone. It is wrong now. Apple rejected on 5.1.1(v) — account
deletion — and deletion only exists inside a signed-in account. A reviewer who
is told sign-in is not required will not sign in, will not find deletion, and
will reject on the same finding twice.

- **User Name:** the demo phone number, in full international form
- **Password:** the review access code

These must match the Worker secrets exactly. Setting them is in Part 3 below.

## Part 3 — The demo credentials must actually work

The reviewer sign-in runs on three Worker secrets. **All three, or the door
stays shut** — two of three is treated as no grant at all.

| Secret | Rule |
|---|---|
| `REVIEW_DEMO_PHONE` | Full international form, matching the User Name field |
| `REVIEW_DEMO_CODE` | **At least 8 characters.** A shorter one turns the grant OFF rather than weakening it — a 6-digit code would be a guessable password on a known account |
| `REVIEW_ACCESS_UNTIL` | A future date. Once it passes, the grant is gone |

Set them:

```
cd /Users/dre/num-worktrees/app-main
npx wrangler secret put REVIEW_DEMO_PHONE --config wrangler.app.jsonc
npx wrangler secret put REVIEW_DEMO_CODE --config wrangler.app.jsonc
npx wrangler secret put REVIEW_ACCESS_UNTIL --config wrangler.app.jsonc
```

**Set `REVIEW_ACCESS_UNTIL` at least 60 days out.** Review takes days; a
rejection and resubmission takes weeks. If that date passes mid-review the
reviewer simply cannot sign in, and you are rejected for a reason that has
nothing to do with your app. There is no warning when it lapses.

Optionally pin it harder with `REVIEW_DEMO_MEMBER` set to the demo account's
id, so a match on the number alone is not enough.

To revoke after approval, delete any one of the three.
