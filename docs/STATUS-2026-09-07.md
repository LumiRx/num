## Fixed during this check

**Internal fields were leaking to every guest.** The reply path stripped internals by naming
them (`_usage, _specialist, _brain, _tried, _ms, _degraded`). `_model` was added to every
brain's return on 30 Aug so a Haiku turn could be priced as Haiku — and nobody added it to
that list, so it shipped to every client for a week, alongside `_blocked` (the moderation
rule a reply tripped). Spotted by reading a real `/api/num` response, not by a test.

Now stripped **by convention** — every `_`-prefixed key is dropped — so the next internal
field is covered the day it is written. `_brain` is still re-published deliberately as
`brain` on a degraded reply. Two tests in `worker/leakguard.test.mjs` pin it; ESLint caught
the one mistake I made doing it.
